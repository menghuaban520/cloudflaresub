# 超时排查

先保持同一节点、同一网络、同一目标网页，每次只改一项。能显示一个测速数值不等于真实 HTTPS 请求成功。

| 现象 | 下一步 | 能判断什么 |
| --- | --- | --- |
| 资源更新列表超时 | 导入 standalone 并确认选中，查看配置正文没有 RULE-SET / DOMAIN-SET | 排除本项目远程规则下载；若仍列出远程资源，检查实际选中配置或其他模块 |
| 两份独立配置都打不开国外网页 | 用同一节点切回已知可用配置比较 | 若旧版也失败，进一步检查节点、服务器、代理链或网络；不能归因于广告规则 |
| 原可用配置正常，新配置失败 | 查看 DNS 错误与实际命中规则；保留失败域名、时间、网络类型 | 隔离 DNS / 隧道设置 / 分流兼容性；不要关闭证书验证掩盖错误 |
| 某 App 在默认版失败、noads 正常 | 检查 REJECT 日志，找误拦的完整域名 | 把确认为必要的域名加入 user-direct 或 user-proxy 后重新生成 |
| 国内服务走代理 | 查域名是否缺少国内条目，或是否命中用户代理覆盖 | 精确补充域名；不因为一个域名失效就把整片共享 CDN 放行 |
| 国外服务意外直连 | 记录 DIRECT 的第一条匹配规则 | 精确补充 user-proxy；同时核对全局路由确为“配置” |
| 只有蜂窝网络失败 | 同一配置、节点和目标在 Wi-Fi 对照，再手动换已知可用备用节点 | 排查网络与协议组合；这一步不证明一定是 UDP 或 MTU 的问题 |
| DNS 检测出现国内解析器 | 记录测试目标、查询路径与节点日志 | 解析器国旗不能单独证明泄漏；国内目标直连使用国内 DNS 属于设计行为 |

问题记录模板：

```text
配置名称/版本：
iOS / Shadowrocket 版本：
Wi-Fi 或蜂窝、运营商：
失败时间与时区：
失败目标域名（去掉私人路径和参数）：
阶段：导入 / 资源更新 / DNS / TLS / 网页请求
同节点使用原可用配置：成功 / 失败 / 未测
同节点使用 standalone-noads：成功 / 失败 / 未测
相关错误与第一条匹配规则（打码）：
```

不用发送真实节点地址、密码或订阅 token。这个构建环境无法访问你的手机隧道，不会把服务器端下载成功当成你家移动网络已修好。
